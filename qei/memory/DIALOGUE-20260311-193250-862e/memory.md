## Шаг 7 – Публичный запуск (Beta → полноценный релиз)

Ниже — **полностью детализированный чек‑лист** для *определённого продукта* (можно просто копировать/переименовать).  

> **Почему это важно?**  
> > Публичный запуск – единственный момент, когда ваш продукт в реальном мире испытывает всевозможные “снипсы”: от‑тайм‑зоны, сетевых задержек, ошибок флагов, до реальных пользовательских сценариев. Чем тщательнее вы подготовите этот момент, тем выше шансы на *позитивный первый отзыв* и *снижение churn‑а* в ближайшихся 90 днях.

### Советы «гонки»:

| Часто встречающиеся проблемы | Как их решить |

| **Бенч‑маркетинг** | Тестировать до и после запуска в одной среде. |

| **ТСП при запуске** | Запланировать суточный «дизайнерский» pull‑request в канале #dev | 
| **Убеждение инвесторов** | Daily Dashboard при публикации KPI. |
| **Первая beta‑вирусная реакция** | Быстро «скидка» + отдельный лендинг «VIP‑аккаунт». |

## Как подключить и использовать

1. **Скопировать** таблицу `Launch Checklist` в ваш таск‑менеджер (Jira / Notion / Asana).  
2. **Назначить ответственных** для каждой задачи (день 0‑день -3).  
3. **Настроить мониторинг**:  
   - Grafana с alert‑ривами: *Server error 5xx > 2%*  
   - New Relic: *Apdex score < 0.8*  
   - Sentry: *Critical errors > 2 per hour*  
4. **Выполнять ежедневную сборку**:  
   - **Кратко**: 10‑минутка «What went ?» + “What follow‑up?”  
   - **Длинно**: 30‑минутная итога + подготовка к следующей фазе.
